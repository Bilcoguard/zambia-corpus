## Summary

Phase 8 sampled 8 of 1928 records this tick. One sampled record (`act-zm-2020-021-customs-and-excise-amendment-act-2020`) carries a malformed on-disk `source_hash` value (`sha256:ca6c004832232876` — only 16 hex characters after the prefix, vs. the 64-hex required by SHA-256). Strict equality comparison against the full 64-hex re-fetched digest therefore produced a "drift" verdict that is **NOT** a real content drift — it is an artefact of the stored hash being too short to verify against. The fetched 64-hex digest **starts with** exactly the stored 16-hex prefix, so the body content is very likely unchanged from when the record was first written.

A read-only enumeration over `records/**/*.json` from this tick's working directory found that this is a **systemic** defect, not an isolated record. All 15 affected records were ingested by the `parliament-pdf-v1.2` parser from `www.parliament.gov.zm`, and form a contiguous run of 2020 Acts (id `act-zm-2020-009` through `act-zm-2020-024`, with `act-zm-2020-010` being the only id in that range *not* present on disk in this corpus).

A separate orthogonal class of records — those with **empty / null** `source_hash` — is also surfaced by the same scan and listed below for the operator's information. This is a different non-negotiable-#2 violation and is **not** what triggered the b0670 HALT, but is included here so that the operator has the complete picture in one diagnostic.

## E — Reproducibility

Anyone with the workspace can reproduce the scan via:

```python
import json, glob
short = []
for f in sorted(glob.glob('records/**/*.json', recursive=True)):
    try:
        with open(f) as fh: rec = json.load(fh)
    except Exception:
        continue
    h = (rec.get('source_hash') or '').strip().lower()
    if h.startswith('sha256:'): h = h[7:]
    if h and (len(h) != 64 or not all(c in '0123456789abcdef' for c in h)):
        short.append((rec.get('id'), rec.get('source_hash'), rec.get('parser_version')))
for s in short:
    print(s)
```
